## 10. 技术替换（2026-10-22）

### 10.1 python-jose → PyJWT

`python-jose 3.5.0` 有 2 个已公开但**无修复版本**的漏洞
（GHSA-3qf3-8w2g-rqmx / PYSEC-2026-4298：算法混淆，DER 编码公钥绕过），
且该库已基本停止维护。

**这两个漏洞对本项目当前不构成实际利用** —— 漏洞前提是「未显式限制算法」，
而本项目两处 `jwt.decode` 都写了 `algorithms=[ALGORITHM]`，且用的是对称密钥、
没有可被用来混淆的公钥。所以这次替换是**消除隐患**，不是堵正在漏的洞。

**迁移风险：已登录用户的 token 会不会失效？** 不会，实测过：

| 方向 | 结果 |
|---|---|
| python-jose 签发 → PyJWT 解码 | 通过，`sub` / `role` / `exp` 正确 |
| PyJWT 签发 → python-jose 解码 | 通过 |
| 旧库签发的 token 访问新服务（`/profile` `/admin/users` `/history`） | 全部 200 |
| 无效 token | 401（拒绝行为不变） |

改动共 3 处：`core/security.py` 的 import 与两处 `except`，
`core/limiter.py` 的 import。依赖树去掉了 `python-jose` 与 `ecdsa`。

### 10.2 CI 增加 ruff 静态检查

**为什么加**：这次排查里 flake8 扫出两处错误分支上的 `F821 未定义名` 与
`F901 无效异常类`，而 164 条 pytest 一条都没抓到 —— 它们不在被测路径上。
静态检查补的正是这块。

**规则选型**：只开 pyflakes（`F`），不开格式类规则。这个仓库有大量研究代码，
一次全量格式化会把 `git blame` 冲掉，收益远小于成本。

对既有代码做了三件事：

| 项 | 处理 |
|---|---|
| `F401` 未使用导入（29 处） | 自动清除；三个 `__init__.py` 的对外符号改用 `__all__` 显式声明 |
| `F541` 无占位符 f-string（3 处） | 自动修复 |
| `F403/F405` star import | 全局忽略 —— `models/` 的既有风格，改它要动整个模型层 |
| `F841` 未使用变量（12 处） | 仅对 `models/` `core/misc/` `core/infer.py` `scripts/` 忽略 |

修完后 `ruff check .` → **All checks passed**，`pytest` → **164 passed**。

### 10.3 还没做的

**`browser-use` → 直接用 Playwright + 函数调用**。它为一个 admin 专用的浏览器
通道引入了 57 个直接依赖（占锁文件 143 个包的 40%），也是 pillow 版本冲突的
根源。收益最大，但需要重写整条浏览器通道，且该通道要真实 LLM 才能验证 ——
成本与风险都高于上面两项，建议单独排期，并先补上浏览器通道的自动化测试。
