# 需求规格

> **本文的性质**：一份**逆向整理**的需求基线 —— 从已经实现的系统反推「它到底
> 满足什么需求、验收标准是什么」。它不是立项时的原始 PRD，也无法证明某个
> 需求是「先有需求后有实现」。
>
> 之所以这样写：项目早期是边做边改的，没有留下需求基线文档。与其编一份
> 看起来像原件的文档，不如把**当前系统实际承担的需求**逐条列清楚，让每一条
> 都能被代码和测试验证。这样它至少有两个用途：给新接手的人一份功能地图，
> 给验收/答辩一个可逐条打钩的清单。

---

## 1. 背景与目标

东北黑土地退化（变薄、变瘦、变硬）监测依赖人工巡田与抽样，周期长、覆盖有限。
本项目用同一地块的前后两期遥感影像做**像素级变化检测**，把「哪里变了、变了多少」
变成可量化、可复核的结果。

**目标**：让不具备遥感专业背景的使用者，能在浏览器里完成「选地块 → 传两期影像
→ 得到变化区域与统计」的全过程，并在此基础上做多模型对比、多时相趋势与灾害定损。

**明确不承诺**：模型输出的是**变化置信度**，不是作物产量、不是减产率、不是理赔金额。

---

## 2. 用户角色

| 角色 | 能做什么 | 边界 |
|---|---|---|
| `user`（普通用户） | 自己的地块、检测、序列、历史、地图、看板、对比、定损、AI | 只看自己的记录 |
| `admin` | 上述全部 + 用户管理 + 查看全库记录 + Agent 浏览器通道 | 记录归属仍按 `user_id` 校验 |
| 游客（未登录） | 仅「单张检测」1 页，可用任意已部署模型 | 不落库、不缓存、不出现于历史；额度只在前端 |

> 游客只放行 1 页是刻意设计，但它会骗人：做浏览器端自动化时必须先建认证会话，
> 否则看起来像「页面全挂了」。

## 3. 功能需求

编号规则：`FR-xx`。每条给出**可验证的验收标准**，尽量指向测试用例或接口。

### 3.1 地块与检测

| 编号 | 需求 | 验收标准 |
|---|---|---|
| **FR-01** | 地块档案：定位、绘制边界、填写属性 | 定位三层降级（后端 IP → 高德 SDK → 浏览器 GPS）任一成功即可；手绘多边形算出的面积与 `AMap.GeometryUtil.ringArea` 一致；表单自动保存 |
| **FR-02** | 单张检测：上传 T1/T2 + 选模型与阈值，返回变化区域与统计 | `POST /detect` 返回 `mask/heat/fusion/score` 四个 URL 与 `ratio`；`ratio` 为百分数（已 ×100） |
| **FR-03** | 批量检测：多组影像一次提交 | 前端并发 3 循环调 `/detect`；任务队列支持暂停/继续/重试/取消；任务态存 IndexedDB，刷新不丢 |
| **FR-04** | 检测去重：同一对影像不重复推理 | 相同 `md5(img1+img2)+模型+阈值+用户` 命中缓存直接返回，且不产生新记录 |
| **FR-05** | 阈值重调：已完成的检测可换阈值重算 | `POST /detect/rethreshold` 用留存的 `_t2.png` 重建融合图，掩膜与融合图不得互相矛盾 |
| **FR-06** | 模型可用性如实暴露 | `GET /detect/models` 区分「已注册」与「权重已部署」；缺权重时选不到 |

### 3.2 结果的组织与复用

| 编号 | 需求 | 验收标准 |
|---|---|---|
| **FR-07** | 检测历史：分页查询、按类型/模型筛选、删除 | `GET /history` 只返回本人（admin 全部）记录；`DELETE /history/{id}` 只删一条 |
| **FR-08** | 检测地图：带坐标的记录在地图上展示 | 只画 `lat_lng` 可解析的记录；支持标记点/热力图两种模式；识别「东经X°，北纬Y°」、逗号、空格三种坐标写法 |
| **FR-09** | 数据看板：总量、分布、趋势 | 总次数、累计变化像素、今日、活跃地块、变化类型分布、模型使用统计、近 7 天趋势 |
| **FR-10** | 结果对比：两条记录并排 | `GET /compare?id1=&id2=`；非 admin 只能对比自己的记录，跨用户返回 403 |
| **FR-11** | 报告导出 | 前端 `jspdf + html2canvas` 合成 PDF；导出内容与页面一致 |

### 3.3 多时相与定损

| 编号 | 需求 | 验收标准 |
|---|---|---|
| **FR-12** | 时序分析：同一地块多期检测串成序列并出趋势 | 挂载时按影像日期重排 `phase_index`；日期非法（非 `YYYY-MM`）拒绝；**日期冲突拒绝而非静默改写**；趋势返回区间、拟合、突变点与声明 |
| **FR-13** | 灾害定损：按受灾等级摊派面积并测算损失 | 系统算出的只有「各级受灾面积」；损失率/亩产/单价必须作为 `assumptions` 单独列出并标注为假设；分级下界可调 |
| **FR-14** | 定损结果不得渲染成系统结论 | 前端与导出文件均须把 `assumptions` 与「假设」标记一起展示 |

### 3.4 AI 与自动化

| 编号 | 需求 | 验收标准 |
|---|---|---|
| **FR-15** | AI 解读：变化分类、分析报告、定损说明草稿 | `POST /ai/*`；LLM 未配置时返回明确错误，不静默降级 |
| **FR-16** | LLM 预算闸：防止循环调用烧额度 | 按天累计调用次数，超过 `LLM_DAILY_CALL_LIMIT` 即拒绝 |
| **FR-17** | Agent 工具通道：自然语言驱动系统功能 | `POST /agent/execute-tools`，登录用户可用；最终调用与 REST 接口同一套服务 |
| **FR-18** | Agent 浏览器通道 | `POST /agent/execute`，**仅 admin**；经 CDP 注入登录态 |

### 3.5 账号

| 编号 | 需求 | 验收标准 |
|---|---|---|
| **FR-19** | 注册/登录/改密/验证码 | JWT 24 小时；口令 bcrypt 存储；登录与注册限流 |
| **FR-20** | 用户管理（admin） | 列表、启用/禁用、重置密码；不可删除最后一个 admin |

## 4. 非功能需求

| 编号 | 类别 | 要求 | 现状证据 |
|---|---|---|---|
| **NFR-01** | 性能 | 单张检测在 GPU 上应达到秒级 | 实测 BIT 46.7 ms、AFCF3D 683.4 ms（SYSU-CD 256×256，RTX 环境） |
| **NFR-02** | 限流 | 检测 30 次/分/用户，历史 30 次/分 | `slowapi` + `get_user_key` |
| **NFR-03** | 安全 | 口令不明文；令牌可撤销（换 `JWT_SECRET`）| bcrypt + JWT；`.env` 不入库 |
| **NFR-04** | 离线可用 | 断网可打开并操作本地已缓存页面 | Service Worker 预缓存 + 依赖全部自托管（无 CDN） |
| **NFR-05** | 部署 | 一条命令在 Ubuntu 上起服务 | `deploy.sh` + Docker Compose |
| **NFR-06** | 数据可迁移 | 支持 SQLite（默认）与 PostgreSQL | `DATABASE_URL` 切换；Alembic 迁移 |
| **NFR-07** | 可观测 | 运行时长、资源、请求统计可查 | `GET /status`；应用日志写 `logs/app.log` |
| **NFR-08** | 依赖可离线 | 模型权重不随仓库分发，缺失时显式失败 | `ModelNotAvailableError` → 503，不静默退回随机权重 |
| **NFR-09** | 精度口径 | 任何界面不得把代理量表述成实测结论 | 定损的 `assumptions`、NDVI 的近似说明、时序的四条 `caveats` |

## 5. 约束与假设

- **影像**：假设为同一地块、已配准的前后两期光学影像；不提供自动配准（只提供配准检查 `POST /detect/check-registration`）。
- **坐标**：地块经纬度来自高德，为 **GCJ-02**。换底图供应商需做坐标转换。
- **授权**：用户对自己上传的影像负责；系统不做版权校验。
- **模型**：不同模型精度差异显著，界面须展示模型名，不隐藏。
- **LLM**：外部服务，可能限流/欠费；必须有明确失败提示。

---

## 6. 范围之外（明确不做）

| 不做 | 原因 |
|---|---|
| 产量预测 / 减产率推算 | 模型输出是变化置信度，与减产率无验证过的换算关系 |
| 真实理赔结算 | 定损只做「面积摊派 + 人为假设」，不接保司系统 |
| 多租户 / 组织隔离 | 当前是单实例、按 `user_id` 隔离 |
| 移动端原生 App | 前端为响应式 Web，无原生包 |
| 自动影像配准 | 只做检查与提示 |
| 卫星影像在线拉取 | 影像由用户上传 |
