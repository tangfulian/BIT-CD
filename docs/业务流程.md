# 业务流程

用户从「手上有一块地」到「得出一个结论」，在系统里实际走的是哪条路。
面向要改这个系统的人 —— **每一步落到哪张表、哪个文件，哪些数是算出来的、哪些是人填的**。

> 讲结构不讲解释的看 [ARCHITECTURE.md](ARCHITECTURE.md)；
> 想先跑起来看 [README](../README.md)。

---

## 0. 一句话

**地块档案是模板不是主键；每次检测产生 5 个文件 + 1 条记录；记录被历史、地图、看板、时序、对比五个下游复用；定损和 AI 是在此之上的解释层，不是新的测量。**

## 1. 全景

```
① 地块配置                 ② 检测                      ③ 结果
┌──────────────┐      ┌────────────────┐      ┌──────────────────┐
│ GPS 定位      │      │ 单张 / 批量     │      │ score  置信度图   │
│ （三层降级）  │      │ 选模型 + 阈值   │      │ mask   二值掩膜   │
│ 手绘边界算亩数│───→  │ T1 / T2 两期影像│───→  │ heat   热力图     │
│ 填档案        │ 快照 │ 命中缓存则直接返回│      │ fusion 叠加在T2上 │
└──────────────┘      └────────────────┘      │ _t2    留存副本   │
   plots                                        └────────┬─────────┘
                                                          ↓ 落库
                                          ┌───────────────────────────────┐
                                          │ detection_results             │
                                          │ ratio / change_pixel /          │
                                          │ lat_lng / 四个 URL / series_id  │
                                          └───────┬───────────────────────┘
                                                  ↓ 五个下游复用
                    历史 · 地图 · 看板 · 结果对比 · 报告导出
                    时序分析（series_id + phase_index 串成多期）
                    灾害定损（在 ratio 之上摊派，不外推减产率）
                    AI 解读 / Agent（自然语言入口）
```

## 2. 逐环节

### 2.1 地块配置 → `plots`

- 定位走**三层降级**：后端 IP 定位 → 高德 SDK → 浏览器 GPS。三层全失败才报错。
- 「绘制地块」用高德 `MouseTool` 画多边形，`AMap.GeometryUtil.ringArea` 直接算平方米。
- 表单自动保存（`LandInfo.autoSave`）。

**关键：`plots` 和检测记录之间没有外键。**

检测时前端把地块的经纬度、地址、变化类型当普通表单字段发过去，记录里存的是
**那一刻的字符串快照**。所以改地块档案不会改历史检测记录 —— 这是有意的
（地块边界本来就会变），但界面上没有明说。

### 2.2 检测 → `POST /detect`

请求字段是 `img1` / `img2`（**不是** t1/t2）、`model`、`threshold`，
外加可选的 `lat_lng` / `location` / `change_type` / `t1_time` / `t2_time` /
`series_id` / `phase_index`。

**缓存键只用四样**：`md5(img1+img2) + model + threshold + user_id`。

> ⚠️ **缓存不包含元数据。** 同一对影像 + 同一模型 + 同一阈值再跑一次，
> 拿回的是**旧记录**，新填的经纬度、地址、日期、变化类型会被**静默丢弃**，
> 而且返回的 `detection_id` 还是旧的。想换元数据只能换影像，或先删旧记录。
> 这一点在「同一块地多期监测」时特别容易踩 —— 见 §2.6。

游客（`user_id=None`）也走这条接口，但**不落库、不缓存、只出图**。

**单张 vs 批量**：批量**不是后端接口**，是前端 `batchDetector.js` 循环调
`/detect`（并发 3），任务队列支持暂停/继续/重试/取消，任务本身存 IndexedDB。

### 2.3 结果：5 个文件

每次检测在 `results/` 下写 5 个文件，以同一个 uuid 开头：

| 文件 | 内容 |
|---|---|
| `_score.png` | 模型输出的逐像素置信度（`score`） |
| `_mask.png` | `score > threshold` 的二值掩膜 |
| `_heat.png` | 热力图着色版 |
| `_fusion.png` | 掩膜与 T2 的 alpha 混合，给人看的 |
| `_t2.png` | **T2 的 256×256 副本，只为事后重调阈值而留** |

留 `_t2.png` 的原因是：融合图 = 混合(T2, 掩膜)，没有它就无法在重调阈值后
重建融合图，只能留下与掩膜自相矛盾的旧融合图。

### 2.4 落库

`detection_results` 一条，含 `ratio`、`change_pixel`、`total_pixel`、
四个 URL、`image_pair_hash`，以及与地块快照对应的字符串字段。

### 2.5 五个下游

| 页面 | 实际取什么 |
|---|---|
| 检测历史 | `/history` 分页，客户端再筛 |
| 检测地图 | 只画 `lat_lng` 能解析的记录；解析器认「东经X°，北纬Y°」、逗号、空格三种写法 |
| 数据看板 | 聚合：总次数、累计变化像素、今日、活跃地块、类型/模型分布、7 天趋势 |
| 结果对比 | `/compare?id1=&id2=`，两条并排；非 admin 只能比自己的 |
| 报告导出 | 纯前端 `jspdf + html2canvas` 合成 |

### 2.6 时序分析 → `image_series`

三步：

1. `POST /series` 建序列（名称、地点、经纬度、面积亩）
2. `POST /series/{id}/records` 把已存在的检测记录挂上去
   - 每期必须带 `t1_time` / `t2_time`，形如 `2024-05`，否则 400
   - **日期冲突会被拒绝，不会静默改写** —— 记录上的日期是既成事实
   - 挂载后按影像日期重排 `phase_index`，**挂载顺序不代表时间顺序**
3. `GET /series/{id}/trend` 出趋势

趋势返回四块：

- `intervals` —— 每个区间一行：天数、`ratio_pct`、`change_area_mu`、
  `rate_pct_per_year`、`rate_area_per_year`
- `fit` —— 对累计变化面积做线性拟合，给 `slope` / `r2` / `n`
- `breakpoints` —— 速率突变点
- `caveats` —— 四句声明，前端必须原样展示

> ⚠️ **`rate_pct_per_year` 是外推值，可能超过 100%。** 实测一组数据里
> 「92 天变化 30.52%」会换算成「122.5%/年」。算术上没错，但变化率超过
> 100% 在业务上是不成立的 —— 读这个字段时要知道它是**按区间线性外推的年化速率**，
> 不是真实年度变化率。

### 2.7 灾害定损 —— 全项目设计最谨慎的一块

模块开头的注释就是它的设计中心：

> 模型给出的 `score` 是「该像素发生变化的置信度」，**不是「减产率」**。
> 两者之间没有任何经过验证的换算关系。

因此严格区分两类数值：

| 类别 | 内容 | 来源 |
|---|---|---|
| 系统算的 | 各级受灾面积 | 由像素占比摊派，可复现 |
| 人给的 | 损失率、亩产、单价 | 调用方假设，放在 `assumptions` 字段 |

前端与导出**必须把后者连同「假设」标记一起展示**，不得渲染成系统测算结论。

分级下界（0.60 / 0.75 / 0.92）是**可调假设**，不是行业标准值；
把它当作「受灾程度」的代理，这个代理关系本身需要实地抽样校验。

### 2.8 AI 与 Agent

- `/ai/*`：变化分类、分析报告、对话。DeepSeek，有每日调用预算上限。
- `/agent/execute-tools`：工具通道，登录用户可用。
- `/agent/execute`：浏览器操控通道，**admin 专用**。

两者都是**入口层**，最终落到 §2.2 与 §2.5 那些服务上，不另起一套语义。

## 3. 数据契约（四条最容易踩的）

1. **`ratio` 是百分数**（已 ×100）。全站直接 `ratio + '%'`，**任何地方再乘 100 都是 bug**。
2. **`lat_lng` 是字符串**，不是两个数字，且是**高德 GCJ-02**。
   换底图供应商（天地图 / Google）会偏 300~600 米。
3. **结果 URL 存的是检测当时的绝对地址**，读出时必须 `rewrite_url`。
   服务器换域名后不做这一步，图片全裂。
4. **时间存 UTC，出参经 `to_local` 转东八区**。各路由曾经各写一份，导致同一系统里
   不同页面时间差 8 小时。

---

## 4. 已知边界

- **地块档案不是主键**（§2.1）。想按地块统计历史检测，现在做不到 —— 只有字符串匹配。
- **缓存不含元数据**（§2.2）。同一对影像换元数据重跑，拿回旧记录。
- **地块页/检测页的图都依赖高德 Key**；没配 `config.local.js` 时地图降级为空白，其余功能正常。
- **`results/` 里的孤儿文件不会自动清理**，需要 `scripts/clean_results.py --delete`。
